# لاگ پلاکینو

`configure_logging()` یک صف محدود ۲۰۰۰ رکوردی و یک نویسندهٔ جداگانه می‌سازد.
فراخوانی تکراری در همان پردازه، نویسندهٔ اضافی ایجاد نمی‌کند. کتابخانه‌های خارجی
به فایل‌های برنامه متصل نمی‌شوند. مسیر خروجی مستقل از پوشهٔ جاری اجرا است:

- `logs/<role>-<pid>/app.jsonl`: رخدادهای INFO و بالاتر
- `logs/<role>-<pid>/error.jsonl`: خطاها همراه traceback

هر فایل تا ۱۰ مگابایت رشد می‌کند و حداکثر ۵ نسخهٔ قبلی نگه می‌دارد.
این سقف برای هر پردازه است؛ پوشه‌های اجراهای قبلی خودکار حذف نمی‌شوند.
جداسازی پردازه‌ها از تداخل چرخش فایل رابط و پردازشگر جلوگیری می‌کند.
زمان‌ها ISO 8601 با منطقهٔ زمانی UTC هستند. مسیرهای URL و مقادیر متداول
password/token در متن خطاها پنهان می‌شوند؛ تنظیمات کامل یا تصاویر را لاگ نکنید.

نام رخداد در `event` و زمینه در فیلدهای مجاز formatter ثبت می‌شود.
`passage_id` تردد خودرو را به OCR، ذخیره، آرشیو تشخیص و `event_id` دیتابیس
مرتبط می‌کند. شمارهٔ پلاک برای دنبال‌کردن این مسیر لازم نیست.

آمار `frame_window` برای دریافت RTSP و صف observation جداست. درصد، نسبت
جایگزینی به تعداد دریافتی همان مرحله در بازه است؛ فریم‌های نرسیده از شبکه،
نمونه‌برداری عمدی خودرو و حذف رویداد در این عدد نیستند. `event_dropped`
حذف یک رویداد بر اثر پرشدن صف است و ERROR ثبت می‌شود.

در صورت پرشدن صف لاگ، تولیدکننده منتظر دیسک نمی‌ماند. تعداد رکوردهای
ازدست‌رفته با `logs_dropped` توسط نویسنده ثبت می‌شود. هنگام خروج طبیعی،
حداکثر سه ثانیه برای تخلیه فرصت داده می‌شود. قطع اجباری پردازه یا خرابی
دیسک می‌تواند باعث ازدست‌رفتن رکوردهای باقی‌مانده شود.

برای DEBUG هنگام راه‌اندازی: `configure_logging(level=logging.DEBUG)`.
برای پایان صریح نویسنده: `shutdown_logging()`؛ خروج طبیعی نیز آن را فراخوانی می‌کند.
