# تنظیم جهت ورود و خروج

## دو خط مستقل

از ریشهٔ پروژه اجرا کنید:

```sh
.venv/bin/python src/computer_vision_v2/select_line_points.py --camera cam2
```

حالت پیش‌فرض دو خط مستقل است: کلیک ۱ و ۲ دو سر خط اول، کلیک ۳ و ۴ دو سر
خط دوم و کلیک ۵ نقطهٔ مشترک سمت داخل پارکینگ است. برای انتخاب نقطهٔ بیرون
از گزینهٔ `--reference-side outside` استفاده کنید. `S` تنظیمات دوربین انتخابی را
ذخیره می‌کند، `R` انتخاب را پاک می‌کند و `Q` یا Escape ابزار را می‌بندد.
پایپ‌لاین را پس از ذخیره دوباره اجرا کنید. نقش هر خط از نقش دوربین گرفته
می‌شود؛ برای `entry_exit` نقطهٔ مشترک مرجع جهت هر دو خط را تعیین می‌کند.
نقطهٔ مرجع نباید روی امتداد هیچ‌کدام از خط‌ها باشد.

تنظیمات جدید در `lines` ذخیره می‌شوند و بر `line` قدیمی اولویت دارند.
خط‌ها فقط بین دو سر خود فعال‌اند و هیچ ضلع اتصال‌دهنده‌ای ندارند.
اولین عبور تشخیص‌داده‌شده یک ایونت می‌سازد و شناسهٔ رهگیری در هر دو خط
مشترکاً از ثبت مجدد منع می‌شود. اگر در یک فریم از هر دو خط عبور تشخیص داده
شود، خط اول در تنظیمات اولویت دارد. تغییر شناسهٔ رهگیری می‌تواند باعث ثبت
مجدد شود؛ سابقه پس از ۶۰ ثانیه دیده‌نشدن شناسه پاک می‌شود.

برای حالت‌های قبلی از `--shape l` یا `--shape straight` استفاده کنید.
انتخاب و ذخیرهٔ یکی از این حالت‌ها `lines` را حذف می‌کند.

برای دوربین `entry_exit` یک `inside_point` در سمت داخل پارکینگ مشخص کنید.
برای مستقل‌شدن از رزولوشن، `coordinate_space` را `normalized` قرار دهید و
مختصات خط و نقطه را بین صفر و یک وارد کنید:

```json
{
  "id": "gate-camera",
  "type": "video",
  "source": "/path/to/video.mp4",
  "coordinate_space": "normalized",
  "line": [[0.2, 0.6], [0.8, 0.6]],
  "dir": "entry_exit",
  "inside_point": [0.5, 0.3]
}
```

در این مثال داخل پارکینگ بالای خط است. عبور به آن سمت `entry` و عبور به
سمت مقابل `exit` تولید می‌کند. نقطه فقط معرف سمت داخل است؛ خودرو لازم نیست
به آن نقطه برسد. ترتیب دو سر خط نتیجه را تغییر نمی‌دهد.

تبدیل از پیکسل: هر `x` را بر عرض تصویر و هر `y` را بر ارتفاع تصویر تقسیم
کنید. بک‌اند نقطهٔ پایین باکس خودرو را با عرض و ارتفاع همان فریم نرمال می‌کند؛
بنابراین تغییر اندازهٔ تصویر، حتی بین فریم‌ها، نیاز به تغییر JSON ندارد.
باکس داخل ایونت همچنان پیکسلی می‌ماند تا مصرف‌کننده‌های بعدی سازگار باشند.

اگر `coordinate_space` وجود نداشته باشد یا `pixels` باشد، مختصات مانند قبل
پیکسلی تفسیر می‌شوند. فقط اضافه‌کردن `normalized` به مختصات پیکسلی کافی نیست؛
اعداد خط و نقطه باید تبدیل شوند. مقادیر خارج بازهٔ صفر تا یک رد می‌شوند.
تغییر برش، حاشیه‌گذاری یا زاویه/زوم دوربین با تغییر اندازهٔ ساده متفاوت است و
به تبدیل مختصات مربوطه یا تنظیم دوباره نیاز دارد.

برای دوربین دوکاره، نبود نقطه، مختصات نامعتبر، خط با طول صفر یا نقطهٔ روی
خط هنگام ساخت تشخیص‌دهنده خطای تنظیمات ایجاد می‌کند. جهت حدس زده نمی‌شود.
تنظیمات قدیمی `entry_exit` باید این فیلد را دریافت کنند.

برای نقش `entry` یا `exit` این فیلد لازم نیست و هر عبور در هر جهت، با همان
نقش دوربین نام‌گذاری می‌شود. تنظیمات پس از راه‌اندازی مجدد پایپ‌لاین اعمال می‌شوند.

در فرم تنظیمات دوربین نیز همین شش مقدار وارد می‌شوند. محور `x` از صفر در
لبهٔ چپ تا یک در لبهٔ راست و محور `y` از صفر در بالای تصویر تا یک در پایین
تصویر است. فیلدهای نقطهٔ داخل فقط برای نقش `entry_exit` فعال و اجباری‌اند.

نقطهٔ پایین و وسط باکس مبنای عبور است و هنگام قرارگرفتن روی خط، آخرین سمت
غیرصفر حفظ می‌شود. محدودیت فعلی یک ایونت برای هر شناسهٔ رهگیری و شرط موفقیت
OCR برای ذخیره در دیتابیس همچنان برقرارند.

اجرای تست‌ها از ریشهٔ پروژه:

```sh
python3 -B -m unittest project.Line_Manager.test_line_detector -v
```
